# Проверка практикума

Дата: 1 октября 2026 года.

## Окружение

- Ubuntu 26.04.1 LTS, ARM64.
- systemd `259.5-0ubuntu3.4`, PID 1.
- cgroups v2.
- Отдельный привилегированный Docker-контейнер с собственным cgroup namespace и временными `/run` и `/tmp`.
- Ядро Docker Desktop `6.12.76-linuxkit`. Это не ядро, поставляемое в Ubuntu Server ISO.

Это окружение использовалось для проверки примеров. Студенты выполняют практикум в VirtualBox; Docker для прохождения не нужен.

## Подтверждённые результаты

| Проверка | Наблюдение |

| Подготовка и синтаксис unit-файлов | Созданы пользователь и файлы, `systemd-analyze verify` завершился без ошибок |

| Restart после SIGKILL | MainPID изменился, NRestarts вырос, HTTP восстановился |
| Ручной stop | Через три секунды служба осталась inactive |
| MemoryMax | 50 MiB при попытке выделить 100 MiB привели к `Result=oom-kill`; в журнале отмечен kernel OOM killer |

| Ручной возврат | Таймер и его state удалены, unit и drop-in основного опыта удалены; повторные prepare и check-environment прошли успешно |

## Границы проверки

Не проверялись установщик VirtualBox, установка Server ISO, реальная загрузка UEFI/GRUB/initramfs, reboot VM, NAT/SSH на macOS и Windows и восстановление снимка. Настройки VirtualBox сверены с официальной документацией. Фактическая работа зависит также от архитектуры и ресурсов хоста.

Состояние службы, код возврата start и один успешный HTTP-ответ проверяют разные свойства. Проверки в README специально используют несколько независимых признаков: журнал, MainPID, владельца сокета и ответ приложения.

## Дополнительные мини-лабораторные Д1–Д6

Дата: **2 октября 2026 года**.

Окружение: Ubuntu 26.04.1 LTS ARM64, systemd `259.5-0ubuntu3.4` как PID 1, cgroups v2, ядро Docker Desktop `6.12.76-linuxkit`. Использован отдельный временный контейнер с собственным cgroup namespace. Учебная VM пользователя для проверки не изменялась.

Блоки Bash извлечены непосредственно из разделов README. Первый проход выполнен от root с проверками состояния systemd, содержимого файлов и HTTP-ответов. После очистки весь сценарий повторён обычным пользователем `student` с `sudo`. В автоматической проверке учтены ожидаемые ненулевые коды: отсутствие файла в общем `/tmp`, отказ HTTP после остановки экземпляра и `is-active` завершившегося oneshot. Для таймера проверка дождалась реального календарного срабатывания; дополнительного ручного запуска вместо него не было.

| Опыт | Подтверждённый результат |
|---|---|
| Д1. RuntimeMaxSec | `sleep 60` завершён при лимите 3 секунды; `ActiveState=failed`, `Result=timeout`; после reset-failed временный unit выгружен |
| Д2. PrivateTmp | Общий `/tmp` не содержит учебного файла; `nsenter --mount` по MainPID читает `hello from private tmp`; служба и её файл удалены при очистке |
| Д3. CPUQuota | Измерения за 5 секунд: 99,1%, 20,1%, 49,9% одного CPU; при повторе от student — 98,8%, 20,0%, 49,9%; MainPID при смене квоты сохранился |
| Д4. Шаблон | На 8082 и 8083 получены разные страницы; после остановки 8082 подключение к нему отклонено, а 8083 продолжил отвечать |
| Д5. Backup timer | Первая копия содержит `version 1`, следующая создана таймером и содержит `version 2`; восстановленная первая копия вернула `version 1`, исходник остался `version 2` |
| Д6. Path activation | Два последовательных появления `request.txt` вызвали две обработки с разным результатом; входной файл удаляется, `.path` остаётся active, oneshot возвращается в inactive с `Result=success` |
| Очистка и повтор | Удалены установленные unit-файлы, страницы, входные файлы и архивы; очищены StateDirectory и отметка Persistent; повторный проход всех шести опытов успешен |

Все шесть постоянных unit-файлов дополнительных опытов прошли `systemd-analyze verify`; Python-файлы проверены синтаксически и использованы при выполнении опытов. Проверены ссылки внутри README и наличие всех упомянутых файлов `extra/`.

Установка пакетов и systemd проверялись внутри контейнера. Эти результаты не заменяют проверку VirtualBox, загрузки VM и подключения по SSH. Измеренные проценты CPU — наблюдение в конкретном окружении: при конкуренции за CPU значения могут быть ниже квоты.
