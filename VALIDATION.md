# Проверка практикума

Дата: 1 октября 2026 года.

## Окружение

- Ubuntu 26.04.1 LTS, ARM64.
- systemd `259.5-0ubuntu3.4`, PID 1.
- cgroups v2.
- Отдельный привилегированный Docker-контейнер с собственным cgroup namespace и временными `/run` и `/tmp`.
- Ядро Docker Desktop `6.12.76-linuxkit`. Это не ядро, поставляемое в Ubuntu Server ISO.

Это окружение использовалось для проверки примеров. Студенты выполняют практикум в VirtualBox; Docker для прохождения не нужен.

## Подтверждённые результаты

| Проверка | Наблюдение |
|---|---|
| Подготовка и синтаксис unit-файлов | Созданы пользователь и файлы, `systemd-analyze verify` завершился без ошибок |
| HTTP | После старта получен HTML; active/disabled до enable, active/enabled после |
| Конфликт порта | Course-web завершился с `Address already in use`; слушающий PID принадлежал port-holder, HTTP продолжал отвечать |
| Восстановление | После остановки port-holder HTTP снова обслуживал course-web |
| Restart после SIGKILL | MainPID изменился, NRestarts вырос, HTTP восстановился |
| Ручной stop | Через три секунды служба осталась inactive |
| MemoryMax | 50 MiB при попытке выделить 100 MiB привели к `Result=oom-kill`; в журнале отмечен kernel OOM killer |
| Hardening | HTTP сохранился; NoNewPrivs=1; запись в `/etc` внутри mount namespace службы получила Read-only file system |
| PrivateTmp | Файл во временном каталоге службы не появился в общем `/tmp` |
| Socket activation | До клиента порт принадлежал PID 1; netcat получил `hello`; экземпляр обработчика завершился |
| Fstab | Findmnt нашёл отсутствующие target/source; исходный `/etc/fstab` не изменился |
| Timer | Таймер сам запустил oneshot на границе минуты, дата появилась в журнале; service завершился и стал inactive |
| Persistent | После периода неактивности таймер догнал пропущенное срабатывание; следующее календарное срабатывание произошло отдельно |
| Завершение | Основная служба и socket остановлены и отключены |
| Ручной возврат | Таймер и его state удалены, unit и drop-in основного опыта удалены; повторные prepare и check-environment прошли успешно |

## Границы проверки

Не проверялись установщик VirtualBox, установка Server ISO, реальная загрузка UEFI/GRUB/initramfs, reboot VM, NAT/SSH на macOS и Windows и восстановление снимка. Настройки VirtualBox сверены с официальной документацией. Фактическая работа зависит также от архитектуры и ресурсов хоста.

Состояние службы, код возврата start и один успешный HTTP-ответ проверяют разные свойства. Проверки в README специально используют несколько независимых признаков: журнал, MainPID, владельца сокета и ответ приложения.
